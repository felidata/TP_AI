# CODEX: Skipper CCD sideband patch anomaly study

Open **[report.html](report.html)** for the self-contained scientific report,
or [report.pdf](report.pdf) for the presentation companion. Full definitions,
literature and limitations are in [METHOD.md](METHOD.md); artifact lineage is in
[PROVENANCE.md](PROVENANCE.md). The original task is [ORIGINAL_PROMPT.md](ORIGINAL_PROMPT.md).

Held-out result: 81.91% effective exposure retained, 22,237 -> 3,903 reconstructed
ROI clusters, background-rate ratio 0.21429, F_equal 3.82235. Rates are normalized
by **surviving pixel-days**, not pixels or raw counts. Largest improvement is in
S101 HDU0. This is relative to active geometry without production MOSKITA masks.
Selection was frozen before test. Later ablations suggest two features are not
beneficial; these are documented without post-test retuning.

## Environment

From the repository root, with Python 3.13 (this run: 3.13.5):

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r CODEX/gpt-6-astra_high/requirements.txt
```

The run uses NumPy, SciPy, Astropy, Matplotlib and scikit-learn only, plus Python's
standard library. Exact core versions are pinned; environment.json records the
observed Python, OS, dependency versions and runtime identity. The standalone PDF
is generated by Matplotlib, requiring no TeX or PDF authoring package. Poppler is
used for visual QA during development, not for numeric reproduction.

## Data, kept outside Git

Expected: 218 `pp_proc*.fits` files, image IDs22..130 for both modules S99 and
S101, each with four 515x3200 HDUs; approximately 5.76 GB total (decimal units).
The public Google Drive location is **NOT_YET_PROVIDED**. Ask the dataset owner
for access; the repository does not claim the data can currently be downloaded
anonymously. Copy/place the FITS files in any directory, preserving basenames:

```bash
export SKIPPER_DATA_DIR=/path/to/pp_proc
python CODEX/gpt-6-astra_high/src/verify_data.py
```

When an actual Drive file ID or shared folder URL is supplied, the optional
downloader works as follows:

```bash
python -m pip install gdown==5.2.0
python CODEX/gpt-6-astra_high/data/fetch_data.py --file-id ACTUAL_FILE_ID --output /path/to/downloads
# Or --url ACTUAL_SHARED_GOOGLE_DRIVE_FOLDER_URL
```

Archives are only downloaded, not extracted automatically. Extract an owner-
provided archive yourself and set SKIPPER_DATA_DIR to the directory directly
containing the FITS files, not the archive or a parent of that directory. Shared
Drive access and Google download limits may require assistance from the owner.
`data/manifest.json` gives SHA-256, byte size, acquisition identity, split,
dimensions, timestamps, calibration and baseline statistics for every input.
The pipeline reads input files only and never writes alongside them.

## Complete reproduction (no notebook, no existing cache required)

From the repository root:

```bash
SKIPPER_DATA_DIR=/path/to/pp_proc bash CODEX/gpt-6-astra_high/reproduce.sh
```

For this local checkout, the equivalent command is:

```bash
SKIPPER_DATA_DIR=../pp_proc bash CODEX/gpt-6-astra_high/reproduce.sh
```

The script verifies hashes first, runs unit checks, reconstructs development
catalogs, selects the model on validation only, reconstructs all data, reproduces
test results at the frozen training threshold, runs independent arithmetic and
stress checks, and regenerates figures, HTML and PDF. Two extraction workers and
one model/BLAS thread limit memory and avoid uncontrolled thread oversubscription.
Allow several minutes; this dataset is modest enough for an ordinary workstation.
All outputs are under this run directory. Only `cache/` contains disposable
intermediates; it is ignored by Git and is rebuilt. Never delete the input data.

For an empty-cache reproduction without deleting an existing cache, rename
`CODEX/gpt-6-astra_high/cache` to an external backup location before running; the
workflow recreates it. `src/audit.py --workers N` controls extraction concurrency.
Individual stages may be run with the commands in reproduce.sh. Once cache and
results exist, `python CODEX/gpt-6-astra_high/src/report.py` regenerates all figures
and reports without retraining (SKIPPER_DATA_DIR is still needed for the image panel).

## Machine-readable outputs

- `results/summary.json`: final **held-out test** result, units, uncertainty,
  configuration, model, seed and scientific code commit. Mass exposure is null.
- `results/operating_points.csv`: 378 rows = 7 methods x 2 tile sizes x 9
  thresholds x 3 splits, including Pareto membership. Repeated unmasked points
  are intentional controls. Training removal target is not test removal fraction.
- `results/selection.json`: validation selection and training threshold;
  initial selection archived in commit `1812e3f`.
- `results/per_hdu.csv`, `per_group.csv`, `test_acquisitions.csv`: aggregation levels.
- `results/ablations.csv`, `reconstruction_checks.csv`, `verification.json`:
  checks, diagnostic failures and sensitivity tests.
- `results/spectrum.csv`, `temporal.csv`, `persistence.csv`: plot/diagnostic data.
- `results/reproduction_check.json`: recorded clean-entry comparison of numeric
  products. Git commit IDs and runtimes naturally differ between reruns; numeric
  outputs and plot assets are compared separately.

The selection grid and definitions live in `configs/analysis.json`. Do not change
them and still call IDs109..130 an untouched final test set. A new scientific
configuration needs new independent data or an explicitly exploratory label.

## Verification boundary

Checks include a separate Python flood-fill, closed-form exposure, direct event
loops, count/rate identities, paired block bootstrap, real ROI erasure, synthetic
injections, spatially displaced masks, feature ablations and calibration/threshold
stress tests. These provide different computational checks within the same agent
run, not an independent scientist/different-model review. Portability is supported
by relative paths, pinned key versions and data hashes; a fresh OS/clean package
installation was not independently tested. See results/reproduction_check.json
for exactly what was reproduced in the observed environment.

Runtime model: `gpt-6-astra`; effort: `high`, confirmed by local session metadata
and CLI configuration. No more specific backend snapshot is exposed. The initial
checkout was an unborn Claude-named branch rather than the stated Codex branch;
this work is isolated to `codex/gpt-6-astra_high` and does not modify `CLAUDE/`.
