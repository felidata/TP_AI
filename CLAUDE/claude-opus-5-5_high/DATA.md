# Data required by this analysis

## What is needed

The 218 processed Skipper-CCD FITS files of the MOSKITA background run
(`pp_proc_skp_mod{S99,S101}_Vv3_bkgd_CLEAR60_NSAMP256_NROW515_NCOL3200_EXPOSURE0_NBINROW1_NBINCOL1_img{22..130}.fits`,
about 5.4 GB). The exact list, sizes, SHA-256 hashes and key header values are in
[`data/manifest.csv`](data/manifest.csv). The FITS files are **not** in this repository.

Point the code at them with

```bash
export SKIPPER_DATA_DIR=/path/to/pp_proc
python scripts/00_manifest.py --verify     # checks names and SHA-256 hashes
```

If `SKIPPER_DATA_DIR` is unset, the default in `configs/default.yaml` is
`../../../pp_proc` relative to this run directory, i.e. `../pp_proc` relative to
the repository root, which is where the dataset lived when this analysis was run.

A public copy does not exist yet. `scripts/download_data.py` is a ready helper for
a future Google Drive folder; its URL in `configs/data_source.yaml` is a documented
placeholder (`PLACEHOLDER_GOOGLE_DRIVE_FOLDER_URL`) and must be filled by the data owner.

## What the files contain (audited from the files themselves)

| item | value |
|---|---|
| files | 218 = 2 modules (S99, S101) × 109 acquisitions (image numbers 22–130, consecutive) |
| acquisition timing | both modules are read simultaneously (identical DATESTART/DATEEND); 2026-04-01 20:50 → 2026-04-23 18:41 |
| readout time | 4.774 h per image (DATEEND − DATESTART), `EXPOSURE = 0` (continuous readout after a clear) |
| HDUs | 4 per file (PRIMARY + 3 extensions), one per amplifier/quadrant, CHID 12–15; no EXTNAME/DETSEC/WCS |
| array per HDU | 515 rows × 3200 columns, float32, `NSAMP = 256` samples already averaged ("processed") |
| units | ADU with a per-row pedestal (not electrons); gain ≈ 206–220 ADU/e⁻ fitted per HDU and image |
| geometry (stored order) | rows 0–511 active, 512–514 vertical overscan; columns 0–7 prescan, 8–3079 active (3072), 3080–3099 overscan, 3100–3199 reverse overscan used for the row pedestal |
| sensor | CCDNROW = 1024, CCDNCOL = 6144; 15 × 15 µm² pixels, 675 µm thick (from the MOSKITA paper, arXiv:2508.06749; assumed identical for S99/S101) → 3.537 × 10⁻⁷ g per pixel |

The mapping HDU → physical corner is not encoded in the headers and was **not** needed:
the analysis treats each (module, HDU) as a separate quadrant.

## Quality decision

One acquisition file (`modS99 … img114`) has a fitted gain ≈ 16 % below its
module/HDU median in all four HDUs (≈180 vs ≈214 ADU/e⁻, noise 0.20–0.21 e⁻ instead
of 0.17 e⁻), uniformly across rows. The pre-declared rule "drop a file if any HDU's
fitted gain deviates by more than 5 % from its module/HDU median" removes it. The
rule uses calibration only (never the 4–7 e⁻ counts). 217 files are used.

## Derived cache (not committed; regenerated by `scripts/01_build_cache.py`)

`cache/images/<file>.npz` holds, for each HDU, the coordinates and integer charge of
every pixel with n ≥ 1 e⁻ and the cluster catalogue; `cache/images/<file>.json`
holds the calibration fit and timing; `cache/calibration_table.csv` tabulates all
872 quadrant-image fits. Total ≈ 110 MB.
